## Deployment, troubleshooting, and reliability

Deploying Budget Quest through Render was my most significant development challenge. Although I had experience with hosted applications, this deployment required me to work through an unfamiliar process for moving my local project to the live web. Missing CSS and configuration or resource-reference problems were not immediately clear from the visible symptoms. I worked through repeated stack traces to narrow down the causes. ChatGPT helped me track troubleshooting progress so that I could avoid repeating approaches I had already tried.

This experience strengthened my understanding of deployment as part of application development. The repository's [Render deployment guide](https://github.com/oegarza1/6325-project-budget-quest-oegarza1/blob/main/DEPLOY_RENDER.md) documents environment variables, the application start command, database migrations, and static-file collection. These details explain why an application that works locally still needs careful preparation for hosting. In a future project, I would establish and document a minimal deployment earlier, then verify it as features are added.

My approach to reliability includes automated tests during builds, deployment gates for failed tests or unmet coverage requirements, peer review, and regular dependency updates. Establishing those checks early is the difficult part; once they are in place, they provide a more dependable basis for adding features. Budget Quest contains concrete testing evidence: its [transaction-deletion tests](https://github.com/oegarza1/6325-project-budget-quest-oegarza1/blob/main/budgetquest/tests_transaction_delete.py) check owner deletion, rejection of another user's deletion attempt, and the asynchronous response. Its [dynamic-quest tests](https://github.com/oegarza1/6325-project-budget-quest-oegarza1/blob/main/budgetquest/tests_quests_dynamic.py) check that administrator-created quests appear in the interface. These files demonstrate specific checks, while my broader build and release practices describe how I approach reliability professionally.

I also want to improve how I organize Django and Python applications as features and interactions increase. My confidence in building a full-stack application does not eliminate the need to strengthen modular design and clarify responsibilities between components.

My AWS experience gives me a useful starting point, but the Render deployment showed the value of understanding approaches outside my usual environment. Potential gaps I should investigate include release rollback, production monitoring, and how much assurance tests and coverage actually provide when users behave unexpectedly.

Course assignments and project materials supported my learning. In CIDM 6325, requirements and deployment documentation helped connect development activities to a complete deliverable. ChatGPT was also an important troubleshooting resource. The coursework refined my use of AI-assisted development, including the conversational approach often called "vibe coding." My responsibility is to understand, review, and test the resulting changes. Keeping a record of attempted fixes was particularly useful because it made troubleshooting more systematic.
